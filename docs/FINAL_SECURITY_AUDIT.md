**Audit Scope:** Browser Extension (MV3), Android Native App, FastAPI Backend, Neon PostgreSQL, Vercel Frontend

## 1. Executive Summary

A comprehensive penetration test and architectural security review was performed across the entire Cyber Raksha AI digital fraud protection ecosystem. Special attention was directed at multi-tenant shared-hosting attacks, Server-Side Request Forgery (SSRF), cross-device telemetry leakage, token hijacking, and open redirects in browser extensions.

All identified Critical and High-severity vulnerabilities have been remediated, verified by automated unit and integration tests, and validated in live cloud staging against Neon PostgreSQL.

## 3. Threat Model & Attack Surface Evaluation

### 3.1 Browser Extension Surface
- **Declarative Net Request Injection:** Rules are compiled deterministically using positive integer IDs generated by `hashIndicatorToId()`. Rule IDs are bounded within `1000` to `899000`. Overrides are assigned `999001` with priority `100`.
- **Cross-Site Scripting (XSS) on Warning Page:** All parameters extracted from query strings in `warning.js` are assigned via `innerText` / `textContent`. No user-controlled string is ever passed to `innerHTML`.
- **Open Redirects:** Interstitial override explicitly verifies `protocol === 'http:' || protocol === 'https:'` before executing `window.location.href`.

### 3.2 Android Surface
- **Keystore Token Protection:** `SecureTokenManager` encrypts the 256-bit device token using AES-GCM with hardware-backed keys provided by Android Keystore.
- **Logcat Hardening:** Retrofit logging interceptor is set to `HttpLoggingInterceptor.Level.HEADERS` in production, ensuring SMS message bodies and numbers are never written to plain-text device logs.
- **Fail-Open Call Handling:** If the network is unavailable or backend latency exceeds 3,000 ms, `CyberRakshaCallScreeningService` invokes `allowCall()`, ensuring legitimate incoming calls are never dropped due to backend outages.

### 3.3 Backend Surface
- **PostgreSQL Injection:** All queries utilize SQLAlchemy ORM with bound parameters. Zero raw string concatenation exists in database queries.
- **Authentication Credentials:** 256-bit device tokens are stored as SHA-256 hashes (`device_token_hash`). Plaintext tokens are returned once during registration and never persisted on the server.
- **Rate Limiting:** Per-device in-memory rate limiting enforces 60 requests/minute for analysis and 20 requests/minute for incident reporting.

---

## 4. Residual Risks & Accepted Limitations
1. **Render Free Tier Cold Starts:** First requests after 15 minutes of inactivity incur a ~30s delay. The browser extension's 1,800 ms timeout ceiling safely fails open to preserve web browsing responsiveness.
2. **Chromium DNR Dynamic Rule Limit:** Chromium enforces a hard ceiling of 5,000 dynamic rules and 1,000 regex rules. Cyber Raksha AI caps rules at 900 to operate with high safety margins.
