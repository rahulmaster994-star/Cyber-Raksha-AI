## 1. Scope & Adversarial Test Boundary

The audio detection module was subjected to adversarial fuzzing and boundary inspection:
1. **Valid Synthetic Waveform Ingestion:** Standard 16kHz mono PCM WAV generated in-memory using Python's `wave` and `struct` libraries.
2. **Corrupted Header / Malformed Audio:** Incomplete RIFF headers followed by random binary bytes.
3. **Non-Audio File Disguise Attacks:** Executable PE (`MZ`) binaries and plain-text files submitted with `audio/wav` or `application/octet-stream` MIME types.
4. **Empty File Injection:** Zero-byte payload submissions.
5. **Privacy & Biometric Boundary Verification:** Inspecting API telemetry to confirm no biometric voiceprints, speaker identity templates, or identifiable biometric traits are stored or exposed.

## 3. Acoustic Architecture vs. Biometric Identification

### Crucial Security Finding (AUD-001)
> [!IMPORTANT]
> **Cyber Raksha AI DOES NOT perform speaker identification, voice verification, or biometric identity authentication.**
> The underlying model is strictly an **acoustic signal consistency classifier**.

The model extracts mathematical signal metrics from the input recording:
- **Zero-Crossing Rate (ZCR):** Measures high-frequency noise typical of neural vocoder artifacts.
- **Spectral Rolloff & Centroid:** Evaluates unnatural energy cutoff frequencies.
- **Spectral Flatness & Bandwidth:** Detects artificial silence or phase-inversion artifacts generated by TTS/voice-cloning algorithms (e.g. ElevenLabs, Tortoise, Vall-E).
- **Energy Variance:** Identifies unnatural synthetic speech dynamics.

### API Disclaimer & Compliance
The `/api/v1/audio/status` endpoint explicitly includes the required governance disclaimer:
> `"Acoustic feature analysis provides a probabilistic estimate of synthetic speech markers. It does NOT verify the speaker's true biometric identity or prove speaker authenticity in a court of law."`

## 4. Operational Limitations
1. **Compressed Codec Degradation:** Audio transmitted over lossy GSM cellular codecs (AMR-NB) or heavily re-encoded WhatsApp audio notes may exhibit degraded spectral resolution, potentially increasing false positives or inconclusive rates.
2. **Short Audio Clips:** Files under 0.5 seconds lack sufficient phoneme representation and return `is_inconclusive: True`.
3. **Engine Safety:** Upload processing runs inside temporary memory buffers with maximum file size limits (25 MB), mitigating storage exhaustion attacks.
